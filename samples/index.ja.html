Tilia

Tilia は、Web 上でインタラクティブな地図や地理空間アプリケーションを構築するための、拡張可能なフレームワークです。静的ファイルのみで動作します（ルート検索機能を除く）。

リポジトリ： https://github.com/hiroaki/Tilia

サンプル

Tilia の各機能はプラグインで提供されるため、すべての機能を単一のアプリケーションに組み合わせることもできます。ただしここでは特徴に応じた機能に絞った構成にしています。

次のリンクから、動作するサンプルを試すことができます。

埋め込みのサンプル

地図をページに埋め込む利用法です。例えば、テンプレートに Tilia の地図を埋め込み、データだけ差し替えることで、複数のコンテンツに対応できます。

  • ./embed/index.ja.html

ビューワーのサンプル

地図アプリの基盤とする利用法です。このサンプルでは GPX と JPG ファイルをドラッグ＆ドロップで入力できます。

  • ./viewer/index.html

クエリーパラメータを受け付けるプラグインを組み込めば、クエリを指定することで初期表示させる GPX ファイルを切り替えることができます。

  • ./viewer/index.html?gpx=../gpx/awaji-sa.gpx（淡路サービスエリア）
  • ./viewer/index.html?gpx=../gpx/tateyama.gpx（立山ハイキング）

エディタのサンプル

ルート検索と、トラックの編集機能について試すことができます（注意：制約があります。後述「ルート検索のバックエンドについて」を参照してください）。また検索結果を GPX ファイルとしてダウンロードすることもできます。

  • ./editor/editor.html

ルート検索のバックエンドについて

Tilia は基本的にクライアントサイドのみで動作しますが、ルート検索の機能はクライアントサイドで完結させることが難しいため、バックエンドでルーティングエンジンを動かす必要があります。

現在のバージョンでは、バックエンドに繋ぐための API ゲートウェイとして Phloem プロジェクトを作成し、それを使用しています。 Phloem は、Tilia のルート検索機能を提供するためのファサードとなり、内部のアダプタを通じてルーティングエンジンにリクエストを転送します。

ルーティングエンジンには GraphHopper の公式 API サービスを利用しています。ただし、このサンプルで使用している API サービスのアカウントはフリーアカウントのため、１日に使用できる回数、およびルート検索時に指定できる地点の数に制限があります（利用者単位ではなく API サービスのアカウント単位の制限です）。制限を超えてしまうと、ルート検索ができずにエラーが表示されます。制限を超えた場合は、しばらく時間をおいてから再度お試しください。

Phloem との連携に利用する GraphHopper はセルフホストすることも可能です。ただし GraphHopper はメモリを大量に消費してしまうため、世界のさまざまな地域を対象にしたルート検索を行いたい場合は、 GraphHopper 公式の API サービスを利用することが現実的です。アカウントを作成し API キーを取得すれば、それを Phloem に設定するだけで Tilia からルート検索を利用できます。 Phloem サーバーを構築する必要がありますが、 Docker を利用できる環境であればコマンドラインひとつで Phloem を起動できます。詳しくは Phloem 構築ガイドを参照してください。
